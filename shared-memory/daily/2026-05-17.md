## Подводные камни / уроки

### X-Accel-Redirect не зашёл
Попробовал заменить readfile-based стриминг на nginx X-Accel-Redirect для скорости. Не получилось — PHP при чтении `$_GET` ВНУТРИ check-access.php стабильно отдавал пустые `$_GET['token']` и `$_GET['expires']`, при том что тот же URL через `debug-args.php` (просто `print_r($_GET)`) показывал данные корректно. После нескольких часов копания (OPcache, php-fpm restart, файл с новым inode через `mv`, опять через `cp`, новое имя файла, fastcgi_split_path_info, fastcgi_buffering off) — НЕ нашёл root cause. Откатил на оригинальный readfile-вариант, который стабильно отдаёт 11 MB/s на Range-запрос — достаточно для 1080p плеера. **TODO для следующей сессии:** разобраться почему фастcgi-pipeline проглатывал query-params для check-access.php но не для debug-args.php при идентичных fastcgi-блоках; возможный кандидат — PHP variable_order или buffering.

### Beget-agent purge-protection
Пакет `beget-agent` сопротивляется удалению: его prerm-скрипт требует marker-файл `/tmp/please-remove-beget-agent` (защита от случайного удаления). Без marker exit 1 → dpkg не покупает purge даже при `--force-all`. Решение: `touch /tmp/please-remove-beget-agent` перед `dpkg --purge`. Дополнительно prerm пытается unmask + start сервис — пришлось вручную unmask перед purge.

### Termius + длинные пасты SSH-ключей
Когда Pavel вставлял мой ssh-ed25519 ключ в Latvia VNC/Termius — клиент склеил его с предыдущей строкой без `\n`. Результат: `authorized_keys` с двумя ключами на одной строке, SSH видит один битый. Урок: **в инструкции к user'у всегда отделять paste от echo `\n`** (через `echo '' >> file` после ключа), или давать команду одной строкой через heredoc.
