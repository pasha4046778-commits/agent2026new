# Техническое задание: система онлайн-записи для ногтевой студии

Версия 0.1 (черновик). Дата: 2026-08-01. Автор: Paganel. Основано на аудите панели DIKIDI Business (проект «Галерея Красоты», company 1272400) — см. research/dikidi-audit.md.

## 1. Цель и контекст

Собственная система онлайн-записи для ногтевой студии — упрощённый аналог DIKIDI, без размывания бренда в чужом каталоге. Заменяет для студии внешний сервис: клиент записывается сам, администратор ведёт журнал, мастера видят своё расписание, все стороны получают уведомления.

Отличие от DIKIDI: не маркетплейс, а частный инструмент студии. Из ~40 разделов DIKIDI берём ядро (записи, услуги, мастера, клиенты, онлайн-запись, уведомления, предоплата), финансово-складские и сетевые модули опускаем или откладываем.

## 2. Роли пользователей

| Роль | Доступ | Платформа |
|---|---|---|
| Клиент | Запись без регистрации, по ссылке/QR | Веб (мобильный браузер) |
| Мастер | Своё расписание и свои записи, отметка о выполнении | PWA на телефоне |
| Администратор | Журнал всей студии, ручные записи, клиенты, услуги, графики, настройки | Веб + PWA |
| Владелец | Всё, что админ + аналитика, настройки студии, управление доступами | Веб + PWA |

## 3. Архитектура и стек

- **Единое приложение** с ролевым доступом (клиент/мастер/админ/владелец) вместо трёх отдельных программ.
- **Стек**: Next.js (App Router) + TypeScript, БД PostgreSQL (или SQLite на старте), Prisma ORM. Хостинг — наш VPS 46.8.79.53 (рядом с hab-site).
- **Мобильные «приложения»** — PWA (installable, push, офлайн-кэш расписания). Нативная обёртка (Capacitor) — опционально позже, если нужен App Store/Google Play.
- **Аутентификация**: клиент — по номеру телефона (без пароля, вход по ссылке/коду при необходимости); мастер/админ — логин по телефону + пароль или magic-link.
- **Уведомления**: Telegram-бот (основной канал, бесплатно) + web-push (PWA) + опционально SMS/WhatsApp через шлюз (платно, позже).

## 4. Функциональные требования

### 4.1. Клиентская онлайн-запись (публичная форма)

Флоу (как в DIKIDI): **Услуга → Мастер → Дата/время → Контакт → Подтверждение**.

- Выбор услуги из каталога с категориями (Маникюр, Педикюр, Мужской педикюр…), показ длительности и цены.
- Выбор мастера ИЛИ «любой специалист» с авто-подбором. Правила авто-подбора (из DIKIDI): отключён / случайный / менее занятый / более занятый. (Опции «услуга дешевле/дороже» для мультицен — опционально.)
- Календарь свободных слотов — генерируются из графика мастера, длительности услуги и уже занятых записей; шаг сетки настраиваемый (5/10/15/30 мин).
- Форма контакта: имя + телефон. Опционально — комментарий.
- Согласие на обработку ПДн (галочка, единоразово, сохраняется в карточке клиента).
- Предоплата (если включена для услуги/правила) — шаг оплаты перед подтверждением (см. 4.8).
- Подтверждение записи на экране + уведомление в мессенджер.
- Мультиязычность формы (RUS/ENG/KAZ) — опционально, на старте RUS.
- Прямые ссылки: общая на студию + доп. ссылки на конкретную услугу/мастера + QR-код для печати.
- Кастомизация внешнего вида: фоновое изображение, цвет кнопок/иконок, название студии, адрес, телефоны, часы (как «Дизайн» в DIKIDI).

### 4.2. Журнал записей (администратор)

- Визуальная сетка: колонки — мастера, строки — время дня; масштаб 5/10/15/30 мин.
- Виды: день / неделя.
- Создание записи вручную: клиент (поиск в базе или новый), услуга(и), мастер, дата/время, комментарий. Плюс «Занять время» (блокировка без клиента — перерыв, личное).
- Перерыв после услуги (настраиваемый буфер после записи).
- Редактирование, перенос (drag&drop желательно), отмена, отметка статуса: ожидает / пришёл / выполнено / неявка.
- Учёт занятости ресурсов/рабочих мест (опционально — если мест меньше, чем мастеров).
- Цветовые пометки записей.

### 4.3. Услуги

- Каталог с категориями. CRUD услуги: название, категория, длительность, цена (фикс или «от»), какие мастера оказывают, активна/архив.
- Персональная и групповая услуга (групповая — опционально для MVP).
- Автогенерация ссылки на запись на конкретную услугу.
- Настройка доступности услуги в онлайн-записи (показывать/скрывать).

### 4.4. Сотрудники (мастера)

- CRUD: имя, должность/категория (Мастер ногтевого сервиса, Администратор…), телефон, фото, доступные услуги.
- Флаг «доступен для онлайн-записи».
- Роль и права доступа (см. 4.10).

### 4.5. График работы

- Настройка рабочего времени по каждому мастеру: выделение дней в календаре → задание начала/конца смены (шаг 15 мин), перерывы.
- Продление графика на период (неделя/месяц вперёд).
- Отображение пометок о записях в графике.

### 4.6. Клиентская база

- Карточка клиента: имя, телефон, число визитов, последний визит, скидка, средний чек, сумма потрачено, статус (активен/заблокирован/удалён), согласие на ПДн, комментарий.
- История визитов клиента.
- Категории/сегменты: постоянные (2+ записи за 3 мес), новые, «заснувшие», потерянные.
- Чёрный список (запрет онлайн-записи; опция «разрешить запись из ЧС»).
- Импорт (CSV/Excel) и экспорт базы.

### 4.7. Уведомления и рассылки

Типы событий (из DIKIDI, 7 видов) — по трём аудиториям:

**Клиенту:** создание записи, напоминание о визите (за N часов), перенос, отмена, приглашение после отмены, поздравление с ДР, запрос отзыва после визита, приглашение на повторный визит.
**Мастеру:** новая запись к нему, изменение/отмена его записи.
**Администратору/владельцу:** новая онлайн-запись, изменение клиентом, отмена клиентом (как «Оповещения» в DIKIDI: настраиваемый список событий + канал).

- Каналы: Telegram (осн.), web-push, e-mail; SMS/WhatsApp опционально.
- Шаблоны сообщений с переменными (имя, услуга, дата, мастер, адрес).
- Ручная отправка сообщения клиенту.
- Массовая рассылка по сегменту (опционально, после MVP).
- Статистика отправки (по статусам и видам).

### 4.8. Предоплата (опционально в MVP, но заложить в модель)

- Правила бронирования (типы, как в DIKIDI): **Оплата/предоплата**, **Отмена/перенос**, **Неявка**, **Предупреждение**.
- Предоплата: фикс или %, привязка к услуге/группе клиентов, условия.
- Приём оплаты — интеграция (у нас есть опыт Prodamus; DIKIDI использует ЮKassa/Тинькофф). На старте можно «предоплата переводом по ссылке».
- Штрафы за отмену/неявку (сумма ≤ 100% записи) — опционально.
- Оферта: текст договора, который клиент принимает при записи.
- Предупреждение при записи (противопоказания, «приходите без покрытия» и т.п.).

### 4.9. Кабинет мастера (PWA)

- Своё расписание на день/неделю.
- Список своих записей с деталями клиента (имя, телефон, услуга, время).
- Push-уведомления о новых/изменённых записях.
- Отметка статуса визита (пришёл/выполнено/неявка).

### 4.10. Доступы и права

- Роли: владелец / администратор / мастер (только просмотр своего) / администратор с ограничениями. (Модель DIKIDI: Создатель, Администратор, Сотрудник с/без прав редактирования, Гость, Заблокирован.)
- Разграничение: кто видит финансы, чужие записи, настройки, клиентскую базу.

## 5. Модель данных (черновик)

- **Studio** (студия): название, адрес, телефоны, часы, настройки онлайн-записи, дизайн.
- **Service**: название, категория, длительность, цена/цена_от, активна, онлайн-видимость.
- **ServiceCategory**: название, порядок.
- **Master**: имя, должность, телефон, фото, роль, доступен_для_записи.
- **MasterService** (M:N мастер↔услуга).
- **Schedule**: master_id, дата, время_начала, время_конца, перерывы.
- **Client**: имя, телефон, скидка, статус, согласие_ПДн, комментарий, сегмент (вычисляемый).
- **Appointment**: client_id, master_id, service_id[], дата/время, длительность, статус, комментарий, источник (онлайн/ручная), цена, предоплата.
- **BookingRule**: тип (оплата/отмена/неявка/предупреждение), параметры, привязка к услуге.
- **Notification**: тип, аудитория, канал, шаблон, статус отправки, дата.
- **User/Role**: доступы.

## 6. Нефункциональные требования

- Мобильный-first (клиенты записываются с телефона).
- Скорость: форма записи открывается < 2 сек.
- Надёжность: бэкап БД в общий ночной цикл (как FrutPed/hab).
- Безопасность: HTTPS, защита ПДн, роли/права, rate-limit на форму записи (антиспам).
- Часовой пояс студии (Актобе, +5).
- Валюта настраиваемая (KZT для «Галереи Красоты», RUB для РФ-студий).

## 7. Этапы разработки

1. **ТЗ + макеты** (текущий этап) — согласовать функции с Павлом.
2. **Ядро данных** — студия, услуги, мастера, графики, генерация слотов.
3. **Клиентская запись** — публичная форма (услуга→мастер→время→контакт→подтверждение) + Telegram-уведомление.
4. **Админ-журнал** — сетка, ручные записи, статусы, клиентская база.
5. **Кабинет мастера + уведомления** — PWA, push по всем событиям.
6. **Настройки онлайн-записи** — правила, дизайн, предоплата (если нужна).
7. **PWA-упаковка, тесты, деплой** на домен.

Оценка: рабочая запись (этапы 2–3) — ~неделя после утверждения ТЗ; полный MVP (1–5) — 3–4 недели.
