# «Движок hab» — сбор требований к админке (живой документ)

Старт: 2026-09-24 (msg 1683). Задача от Павла: заложить расширенный функционал сразу для трёх вертикалей — **кафе / услуги / магазины**; клиент сам выбирает, чем пользоваться; расширяемость и обновляемость. Собираем «наиболее нужные функции» не торопясь — документ пополняется.

Источники: наши админки (Арзу QR-меню, booking-app, админка hab, FrutPed), аудит DIKIDI (research/dikidi-audit.md), qrpay.kz, практика WooCommerce/Tilda/InSales, специфика KZ (Kaspi, 2ГИС, WhatsApp).

Приоритеты: 🅰 ядро v1 (без этого не продать) · 🅱 v1.5 (сильно хотят, можно докатить) · 🅲 потом/по запросу.

## Архитектурные принципы (чтобы «расширять и обновлять» не стало болью)

1. **Одно ядро — плагины-вертикали.** Ядро (auth, контент, медиа, лиды, настройки, статистика) не знает про блюда/услуги/товары; вертикали — отдельные модули со своими таблицами и экранами. Клиенту включаем нужные тумблером.
2. **SQLite на клиента** (проверено: hab, booking): один файл = простые бэкапы, изоляция, дешёвый хостинг.
3. **Контент клиента отделён от кода движка** — обновление движка = замена кода без миграции контента (миграции схемы версионируем).
4. **Мобайл-фёрст админка**: шеф Арзу и мастера правят всё с телефона. Каждый экран проектируем сначала под палец.
5. **Никаких обязательных подписок на нас**: всё работает без студии; поддержка — опция, не привязка (наш ответ DIKIDI/qrpay, где клиент заперт в чужом SaaS).
